# Native x64 functional CI

`.github/workflows/native-x64-qualification.yml` runs manually or on an explicit push to `qualification/native-x64-20260929`. The dedicated branch permits initial qualification before the workflow exists on the default branch. It runs the selected workflow ref at its exact GitHub SHA on `macos-15-intel` and `ubuntu-24.04`, independently. It never publishes, deploys, installs tmux-ide globally or touches a default tmux service. Build dependencies are installed in ephemeral runners. Every native fixture uses private sockets; cleanup checks refuse a preexisting tmux process and fail if a new tmux process remains. Individual fixtures own shell/control-child and socket teardown; the outer process receipt specifically audits tmux servers, not arbitrary descendants.

After this workflow is reviewed and available to GitHub, an authorized operator can select **Native x64 functional qualification → Run workflow** on the frozen candidate ref (or `gh workflow run native-x64-qualification.yml --ref <frozen-ref>`). No invocation is part of the source change. Record run URL and SHA; both matrix jobs and every selected assertion must pass. An existing workflow YAML or a successful renderer build is not execution evidence.

Evidence artifacts retain exact candidate/host facts, native patch provenance, sanitizer/build/runtime logs, the complete production native closure including manifest/licenses, Vitest JSON and cleanup receipt. Validators reject wrong executable/dependency architecture, changed/missing manifest files, missing test files, zero-test suites and skipped/todo tests. `functional.json` appears only after sanitizer success and full selected suite verification; job success also requires cleanup success.

The eight selected daemon files exercise production observer batches/gaps/replacement, projector attribution, authored wrapper/completion, parser literals, atomic snapshots, dual recovery, and native/plain/mixed recovery. This complements the native sanitizer adversarial suite. It does not execute a compiled TUI, installed CLI/MCP/SDK campaign or physical SSH journey. It does not claim the entire original C4 gate: long real lease-boundary idle and per-platform workload/performance budgets remain separate qualification. Hosted-runner timings are retained diagnostics, never acceptance evidence for performance. Existing ARM64 evidence is independent.

Local source checks: `node --test scripts/lib/native-x64-qualification.test.mjs`; formatting/lint and workflow YAML parsing are cheap checks. Running the workflow's sanitizer/build/live commands locally is not required to review this change.

Sanitizer invocation supplies an exclusive `--evidence-dir` beneath the retained proof directory. All eleven Python fixtures export only their own bounded regular ASan/UBSan files before deleting scratch state. A native failure also retains the sanitizer executables and hashes for symbolization; on Darwin a failure-only `dsymutil` invocation has a 30-second kill deadline and runs before scratch object deletion; export failure never replaces the original native exception. No global `/tmp` scan is used. Offline collector checks: `python3 native/tmux/tests/native-test-evidence.test.py`.
